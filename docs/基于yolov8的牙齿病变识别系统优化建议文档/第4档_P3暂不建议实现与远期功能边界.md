# 第四档_P3暂不建议实现与远期功能边界

## 第四档说明

第四档不是当前要开发的功能，而是需要明确边界，避免项目范围失控。当前项目是基于已训练 YOLO 模型的牙齿病变前台识别系统，不是训练平台、医院系统或商业诊所管理平台。

以下内容不建议当前实现，最多作为远期设想写入文档。

---

# 一、不建议实现：在线复训练

## 1. 不建议原因

在线复训练需要：

1. 训练代码。
2. 训练数据集。
3. 标注质量控制。
4. GPU 服务器。
5. 训练参数配置。
6. 模型版本管理。
7. 训练失败恢复。
8. 模型上线流程。

普通用户不具备这些条件。强行在前台中加入复训练，会让项目定位混乱，也会导致大量不可控问题。

## 2. 当前项目应如何处理

不要出现以下按钮：

```text
重新训练
继续训练
一键训练
加入训练集
用当前病例优化模型
```

如果用户反馈检测不准，可以提供：

```text
添加备注
保存病例
导出报告
```

但不要把备注变成训练数据闭环。

---

# 二、不建议实现：主动学习

## 1. 不建议原因

主动学习听起来高级，但它需要完整的数据和训练闭环：

1. 自动挑选高不确定性样本。
2. 用户或医生标注。
3. 标注质量审核。
4. 训练集更新。
5. 模型重新训练。
6. 新模型评估。
7. 新模型上线。

这明显超出当前前台识别系统范围。

## 2. 当前项目应如何处理

可以保留简单用户反馈，例如：

```text
用户备注：该结果疑似不准确
```

但不要进一步做主动学习流程。

---

# 三、不建议实现：在线标注平台

## 1. 不建议原因

在线标注平台是一个独立项目，需要：

1. 图片管理。
2. 标注工具。
3. 框编辑。
4. 标签管理。
5. 标注任务分配。
6. 标注质量审核。
7. 数据集导出。
8. 多人协作。

这些不是当前项目目标。

## 2. 可以保留的轻量替代

可以保留：

- 病例备注。
- 检测结果备注。
- 用户反馈文本。
- 保存当前检测记录。

不要实现完整画框标注系统。

---

# 四、不建议当前实现：PACS 与医院系统集成

## 1. 不建议原因

PACS、DICOMweb、HIS、RIS 等医院系统集成工程量非常大，并且涉及医疗数据安全和合规问题。当前项目如果只是本地前台识别工具，不应该把这类系统集成作为开发重点。

## 2. 可作为远期设想

如果以后要产品化，可以考虑：

1. DICOM 文件读取。
2. DICOM 元数据脱敏。
3. 本地 Orthanc 测试。
4. OHIF 查看器联动。
5. 推理 API 接口。

但这不应进入当前主要开发任务。

---

# 五、不建议当前实现：多用户权限系统

## 1. 不建议原因

当前项目是本地 Gradio 前台系统，多用户权限不是核心需求。实现登录、角色、权限、审计日志会显著增加复杂度，但对识别功能帮助不大。

## 2. 可选远期方向

如果以后需要局域网多人使用，可以考虑：

1. 简单登录。
2. 管理员和普通用户区分。
3. 病例访问权限。
4. 操作日志。

当前阶段不建议做。

---

# 六、不建议实现：保险、收费、诊所管理

## 1. 不建议原因

这些功能属于商业牙科软件或诊所管理系统范畴，与 YOLO 牙齿病变前台识别系统无关。

不要实现：

- 收费管理。
- 保险理赔。
- 预约管理。
- 患者排班。
- 诊所运营报表。
- 治疗计划收费代码。

这些会严重偏离项目主题。

---

# 七、可以远期考虑但不优先：DICOM 支持

## 1. 为什么不优先

如果当前输入主要是普通图片格式，例如 PNG、JPG、JPEG、BMP、TIFF，那么 DICOM 支持不是最紧急功能。

DICOM 支持会带来：

1. 元数据隐私问题。
2. 窗宽窗位处理问题。
3. 多帧图像问题。
4. 中文和编码问题。
5. 医疗影像显示规范问题。

## 2. 如果未来要做

建议只做轻量版本：

1. 支持单个 .dcm 文件导入。
2. 使用 pydicom 转为普通图像。
3. 默认不显示患者隐私字段。
4. 导出报告时提示 DICOM 信息已脱敏。
5. 不做 PACS 对接。

---

# 八、可以远期考虑但不优先：FastAPI 推理接口

## 1. 为什么不优先

FastAPI 接口有助于系统扩展，但当前项目的主要交付形态是 Gradio 前台。对普通用户而言，API 不直接提升使用体验。

## 2. 什么时候适合做

如果后续需要：

1. 接 Electron 桌面端。
2. 接独立前端。
3. 接局域网服务。
4. 接第三方系统。
5. 做自动化批处理。

再考虑 FastAPI。

## 3. 远期接口示例

```text
GET /health
GET /models
POST /predict
POST /batch_predict
```

当前阶段不优先。

---

# 九、最终边界结论

当前项目应坚持：

```text
已训练模型 + 本地前台识别 + 结果查看 + 报告导出 + 病例记录 + 辅助建议
```

当前项目不应扩展为：

```text
训练平台
标注平台
主动学习平台
医院系统
诊所管理系统
保险理赔系统
```

给 Codex 开发时，如果它主动提出训练、复训练、主动学习、在线标注、医院系统集成等方向，应明确拒绝，并要求它回到前台识别系统优化主线。
