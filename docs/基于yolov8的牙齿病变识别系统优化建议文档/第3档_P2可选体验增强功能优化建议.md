# 第三档_P2可选体验增强功能优化建议

## 第三档说明

第三档功能属于体验增强和展示优化。它们不是当前必须完成的核心功能，但实现后会让项目更易演示、更易理解、更像成熟软件。

第三档包含六个功能：

1. 演示样例库。
2. 牙位粗定位。
3. 检测框显示开关。
4. 结果图片单独下载。
5. 界面新手引导。
6. 异常处理提示优化。

---

# 功能一：演示样例库

## 1. 功能目标

为了方便答辩、演示和用户试用，建议内置少量脱敏样例图。用户无需自己准备图片，也可以快速体验系统功能。

## 2. 使用场景

1. 答辩现场快速演示。
2. 老师检查项目时快速测试。
3. 用户第一次打开系统时快速了解流程。
4. 避免现场没有合适图片导致演示失败。

## 3. 功能设计

在上传区域附近增加：

```text
示例图片
[示例 1] [示例 2] [示例 3]
```

用户点击后，自动加载对应图片到上传框，并可点击开始分析。

## 4. 样例管理

新增目录：

```text
assets/examples/dental
```

样例文件命名使用中文：

```text
示例_龋齿.png
示例_根尖周病变.png
示例_阻生牙.png
示例_无明显目标.png
```

如果图片涉及真实病例，必须确认脱敏。

## 5. 示例说明

每张示例图可以配一个说明 JSON：

```text
示例图片说明.json
```

内容包括：

- 文件名。
- 示例名称。
- 预期类别。
- 说明文本。
- 是否脱敏。

## 6. 验收标准

1. 用户可以点击加载示例图。
2. 示例图可正常检测。
3. 示例图不影响手动上传。
4. 示例图文件名使用中文。
5. 示例说明不包含隐私信息。

# 功能二：牙位粗定位

## 1. 功能目标

不做复杂牙齿编号模型，只做基于检测框位置的粗略区域提示。这样可以提升用户理解，但不引入新的深度学习任务。

## 2. 设计边界

本功能不是专业牙位编号，不输出精确牙号。只输出粗略位置，例如：

- 左上区域。
- 右上区域。
- 左下区域。
- 右下区域。
- 前牙区。
- 后牙区。
- 中央区域。

## 3. 实现思路

根据 bbox 中心点相对图片宽高的位置进行判断。

示例规则：

```text
x < 1/3 宽度：左侧区域
1/3 <= x <= 2/3 宽度：中间区域
x > 2/3 宽度：右侧区域

y < 1/2 高度：上方区域
y >= 1/2 高度：下方区域
```

组合输出：

```text
左上区域
右下区域
中上区域
```

如果是全景片，左右方向可能与患者实际左右存在镜像问题，因此必须写成“图像左侧/图像右侧”，不要写成患者左侧或患者右侧。

## 4. UI 展示

检测表新增字段：

```text
图像区域
```

示例：

| 类别 | 中文名称 | 置信度 | 关注等级 | 图像区域 |
|---|---|---:|---|---|

## 5. 报告展示

报告中写：

```text
区域提示：图像右下区域
```

并加说明：

```text
区域提示仅根据图像中检测框位置粗略计算，不等同于专业牙位编号。
```

## 6. 验收标准

1. 每个检测框能输出粗略图像区域。
2. 无检测框时不输出区域。
3. 报告中包含区域提示。
4. 不输出精确牙号。
5. 不把图像左右误写成患者左右。

# 功能三：检测框显示开关

## 1. 功能目标

当一张图中检测框较多时，用户可能希望只查看某一类病变。建议支持按类别显示或隐藏检测框。

## 2. 功能设计

在检测结果区增加复选框：

```text
显示类别：
[x] 龋齿
[x] 根尖周病变
[x] 阻生牙
```

用户取消某类后，结果图中隐藏对应检测框。

## 3. 实现建议

当前绘图逻辑在推理后生成 annotated 图。如果要支持动态开关，可以保存原始模型输入图和 detections，然后根据用户选择重新绘制结果图。

建议将绘制逻辑封装为函数：

```python
def draw_detections_with_filter(image, detections, visible_classes):
    ...
```

## 4. 注意事项

1. 不要重新运行模型，只重新绘制图片。
2. 类别隐藏只影响显示，不应删除检测结果。
3. 导出报告时使用当前显示状态还是完整状态，需要明确。建议默认报告导出完整检测结果。

## 5. 验收标准

1. 可以按类别隐藏检测框。
2. 隐藏不触发重新推理。
3. 检测表仍保留完整结果。
4. 切换批量图片后开关仍可用。
5. 报告导出逻辑明确。

# 功能四：结果图片单独下载

## 1. 功能目标

用户有时只想下载检测结果图，不需要完整报告或数据包。因此应提供单独下载按钮。

## 2. 功能设计

在结果图附近增加：

```text
下载检测结果图
下载模型输入图
下载原始上传图
```

建议第一阶段只做：

```text
下载检测结果图
```

## 3. 文件命名

下载文件建议使用中文命名：

```text
检测结果图_原图片名_时间戳.png
```

例如：

```text
检测结果图_病例001_20260609_153000.png
```

## 4. 验收标准

1. 检测完成后可以下载结果图。
2. 文件名为中文可读名称。
3. 未检测时按钮不可用。
4. 批量切换图片后下载对应图片。
5. 不影响报告导出。

# 功能五：界面新手引导

## 1. 功能目标

让第一次使用系统的用户知道怎么操作，减少困惑。

## 2. 设计建议

在首页或检测工作台顶部加入简短流程：

```text
使用流程：
1. 上传牙科影像
2. 点击开始分析
3. 查看检测结果和辅助建议
4. 根据需要保存病例或导出报告
```

不要写太长，避免界面变啰嗦。

## 3. 可折叠帮助

详细说明放入 Accordion：

```text
使用说明
```

内容包括：

- 支持图片格式。
- 置信度含义。
- CLAHE 适用情况。
- 报告导出说明。
- 安全声明。

## 4. 验收标准

1. 首页能看到简短流程。
2. 详细说明可折叠。
3. 不影响主界面简洁度。
4. 文案自然，不像开发日志。

# 功能六：异常处理提示优化

## 1. 功能目标

当前错误提示有些可能偏工程化。普通用户遇到错误时，需要知道应该怎么处理，而不是只看到异常栈或底层报错。

## 2. 常见错误场景

需要优化：

1. 模型文件不存在。
2. 模型文件格式不支持。
3. CUDA 不可用。
4. 图片文件损坏。
5. 上传文件格式不支持。
6. AI 接口失败。
7. API Key 缺失。
8. 存储目录不可写。
9. 导出报告失败。
10. 批量检测部分失败。

## 3. 提示格式建议

错误提示应包含：

1. 发生了什么。
2. 可能原因。
3. 用户可以怎么做。

示例：

```text
模型文件不存在。

可能原因：
- 模型文件被移动或删除。
- 设置中的模型路径不正确。

建议处理：
- 进入设置页重新选择模型文件。
- 点击“测试模型”确认模型可以加载。
```

## 4. 代码实现建议

新增：

```text
src/dental_detection/error_messages.py
```

将常见错误转换为用户友好提示。

## 5. 验收标准

1. 常见错误不直接暴露复杂异常。
2. 提示中包含解决建议。
3. 开发调试信息可以保留在日志中，但不要直接吓到用户。
4. AI 接口错误提示清晰。
5. 导出失败提示清晰。
