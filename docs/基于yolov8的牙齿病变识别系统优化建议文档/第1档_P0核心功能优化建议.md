# 第一档_P0核心功能优化建议

## 第一档说明

第一档是当前项目最应该优先开发的功能。这些功能直接服务于“已训练模型的前台识别系统”定位，不需要训练数据集、训练代码或服务器资源，能够显著提升普通用户体验和项目完成度。

第一档包含六个功能：

1. 正式 Word 或 PDF 报告导出。
2. 批量检测结果总览。
3. 结果风险等级与置信度解释。
4. 结果图交互增强。
5. 病例记录增强。
6. 图像质量检测增强。

# 功能一：正式 Word 或 PDF 报告导出

## 1. 功能目标

当前项目已经可以导出单图报告压缩包，但压缩包更像开发者数据包。普通用户更需要一个可以直接打开、打印、发送、归档的正式报告文件。

建议新增：

- 导出 Word 报告。
- 后续可选导出 PDF 报告。
- 保留原有压缩包导出功能。

优先建议实现 Word 报告，因为 Word 对中文更友好，也方便用户二次修改和另存为 PDF。

## 2. 用户使用流程

用户完成单张检测后，界面提供两个导出入口：

1. 导出正式报告。
2. 导出开发数据包。

推荐按钮文案：

```text
导出 Word 报告
导出 ZIP 数据包
```

其中：

- Word 报告面向普通用户。
- ZIP 数据包保留现有完整数据，面向开发、调试、备份。

## 3. 报告内容结构

### 3.1 报告标题

报告开头使用：

```text
牙齿病变区域辅助识别报告
```

标题下方显示基础信息：

```text
生成时间：2026-xx-xx xx:xx:xx
图片名称：xxx.png
使用模型：xxx
报告类型：单张影像检测报告
```

### 3.2 安全声明

报告顶部必须醒目显示：

```text
本结果仅供辅助参考，不能替代专业牙科医生诊断。
```

安全声明应加粗或使用醒目样式。不要隐藏在报告末尾。

### 3.3 图像展示

报告中至少包含：

1. 原始上传图。
2. 检测结果图。

如果用户开启了 CLAHE，则建议同时包含：

3. 实际送入模型的图像。

推荐排版：

```text
一、影像与检测结果

图 1 原始上传图
图 2 检测结果图
图 3 实际送入模型的图像
```

第一阶段可以上下排列，不必追求复杂并排布局。稳定性优先。

### 3.4 检测摘要

报告中应自动统计检测结果。

如果检测到目标框：

```text
本次共检测到 3 个疑似目标区域。

类别统计：
- 龋齿：1 处
- 根尖周病变：1 处
- 阻生牙：1 处
```

如果没有检测到目标框：

```text
本次未检测到明确目标框。该结果不代表不存在病变，仍需结合原始影像质量、临床症状和专业牙科检查进行判断。
```

### 3.5 检测框明细表

表格字段建议：

| 序号 | 类别 | 中文名称 | 置信度 | 关注等级 | x1 | y1 | x2 | y2 |
|---|---|---|---|---|---|---|---|---|

其中中文名称映射：

- Caries：龋齿
- Periapical_Lesion：根尖周病变
- Periapical Lesion：根尖周病变
- Impacted：阻生牙

关注等级规则：

- 置信度大于等于 0.70：重点关注。
- 置信度大于等于 0.40 且小于 0.70：建议复查。
- 置信度小于 0.40：低置信度参考。

注意：关注等级不是疾病严重程度，也不是诊断结论。

### 3.6 图像质量提示

将界面中的图像质量提示写入报告，例如：

```text
图像尺寸：xxxx x xxxx
平均亮度：xx.x
对比度估计：xx.x
提示：图像整体偏暗，建议确认牙片曝光或阅片窗宽窗位。
```

后续如果增加模糊检测、过曝检测、欠曝检测，也应写入报告。

### 3.7 辅助建议

报告中加入当前系统生成的辅助建议。辅助建议可以来自内置规则，也可以来自 AI 接口，但必须遵守安全边界。

建议标题：

```text
辅助建议
```

内容要求：

1. 不输出最终诊断。
2. 不提供处方。
3. 不提供药物剂量。
4. 不建议自行用药。
5. 始终提示用户结合专业牙科医生检查。

### 3.8 技术参数摘要

技术参数放在报告后半部分，避免一开始就让普通用户困惑。

建议字段：

```text
推理尺寸：1280
置信度阈值：0.25
IoU 阈值：0.70
CLAHE 增强：是 / 否
运行设备：cpu / cuda:0
模型名称：xxx
```

不建议在正式报告里展示过长的本地模型路径，除非放在附录。

## 4. 代码实现建议

新增文件：

```text
src/dental_detection/reporting.py
```

建议定义数据结构：

```python
@dataclass

```

建议函数：

```python

    ...
```

注意：如果代码中写注释，注释必须使用中文。

## 5. 依赖建议

优先使用：

```text
python-docx
```

需要更新 requirements.txt：

```text
python-docx>=1.1.2
```

如果后续做 PDF，可以考虑：

- 先生成 HTML，再让用户用浏览器打印为 PDF。
- 或使用专门 PDF 库，但要重点处理中文字体。

## 6. 边界处理

必须处理：

1. 没有检测结果时也能导出报告。
2. 图片对象缺失时给出明确错误。
3. 文件名包含中文、空格、特殊字符时安全保存。
4. 同一时间重复导出不覆盖旧文件。
5. 存储目录不存在时自动创建。
6. 导出失败时不影响当前检测结果。
7. 报告中不写入 API Key。
8. 报告中不出现诊断性措辞。

## 7. 验收标准

1. 完成单图检测后可以导出 Word 报告。
2. Word 报告可以在 Word 或 WPS 中正常打开。
3. 报告图片显示正常。
4. 检测表格字段完整。
5. 无检测框时也能生成报告。
6. 报告包含安全声明。
7. 原有 ZIP 导出不受影响。
8. 批量检测、病例记录、AI 问答功能不受影响。

# 功能二：批量检测结果总览

## 1. 功能目标

当前项目支持批量检测和逐张查看，但批量检测结束后缺少一个整体统计界面。用户批量上传后，最想快速知道哪些图片值得重点查看，而不是逐张下拉切换。

新增“批量检测总览”，在批量分析完成后显示整体统计和重点关注列表。

## 2. 总览内容

### 2.1 基础统计卡片

显示：

```text
图片总数
成功处理数量
处理失败数量
检测框总数
涉及类别
平均置信度
最高置信度
```

示例：

```text
本次批量分析共处理 20 张图片，其中 19 张成功，1 张失败，共检测到 35 个疑似目标框。
```

### 2.2 类别统计表

字段建议：

| 类别 | 中文名称 | 检测框数量 | 涉及图片数 | 最高置信度 | 平均置信度 |
|---|---|---:|---:|---:|---:|

### 2.3 重点关注图片列表

字段建议：

| 排名 | 图片名称 | 最高类别 | 最高置信度 | 检测框数量 | 关注等级 |
|---|---|---|---:|---:|---|

排序规则：

1. 按最高置信度降序。
2. 置信度相同则按检测框数量降序。
3. 仍相同则按图片名称排序。

### 2.4 失败图片列表

如果有图片处理失败，应独立展示失败原因。

示例：

```text
以下图片处理失败：
- xxx.png：图片文件损坏
- yyy.jpg：模型推理失败
```

不要只把失败信息追加到第一张图片的建议文本里。

### 2.5 无检测结果图片列表

显示未检测到目标框的图片数量，并提供折叠列表。

示例：

```text
未检测到明确目标的图片：5 张
```

## 3. 代码实现建议

新增文件：

```text
src/dental_detection/batch_summary.py
```

建议函数：

```python
def build_batch_summary(batch_state: list[dict[str, Any]], batch_errors: list[str] | None = None) -> dict[str, Any]:
    ...
```

返回结构建议：

```python
{
    "图片总数": 20,
    "成功处理": 19,
    "处理失败": 1,
    "检测框总数": 35,
    "类别统计": [...],
    "重点关注图片": [...],
    "失败图片": [...],
    "无检测结果图片": [...]
}
```

所有注释和字段命名面向用户时使用中文。内部变量可以使用英文，但注释必须使用中文。

## 4. 前端实现建议

在批量分析区域或结果面板中新增：

```text
批量分析总览
```

推荐布局：

1. HTML 卡片展示基础统计。
2. Dataframe 展示类别统计。
3. Dataframe 展示重点关注图片。
4. Accordion 展示失败图片和无检测图片。

## 5. 导出联动

批量导出时，把总览写入导出包。

建议新增文件：

```text
批量检测总览.json
批量检测总览.csv
批量检测总览.html
```

如果后续实现批量 Word 报告，总览应作为第一页。

## 6. 边界处理

1. 批量文件为空时保持原有错误提示。
2. 全部失败时显示明确错误。
3. 部分失败时仍展示成功图片统计。
4. 全部成功但无检测框时，总览仍正常显示。
5. 类别未知时显示原类别名。
6. 置信度异常时按 0 或未知处理。
7. Top 列表不足 10 张时显示实际数量。

## 7. 验收标准

1. 批量检测完成后显示总览。
2. 类别统计正确。
3. 重点关注列表排序正确。
4. 失败图片独立展示。
5. 无检测结果图片能统计。
6. 批量导出文件包含总览。
7. 原有逐张查看功能不受影响。

# 功能三：结果风险等级与置信度解释

## 1. 功能目标

当前检测表展示 confidence，但普通用户未必理解其含义。需要将置信度转化为更容易理解的关注等级，同时说明置信度不是诊断结论，也不是疾病严重程度。

## 2. 等级规则

建议统一规则：

```text
confidence >= 0.70
等级：重点关注
说明：模型对该目标框较有把握，建议结合原始影像和医生检查重点复核。

0.40 <= confidence < 0.70
等级：建议复查
说明：模型检测到可疑区域，但把握程度中等，建议由专业人员结合影像复核。

confidence < 0.40
等级：低置信度参考
说明：模型把握较低，仅作为提示，不应作为诊断依据。
```

无检测框时：

```text
未检测到明确目标。该结果不代表不存在病变，仍需结合症状、影像质量和专业检查判断。
```

## 3. 表格字段调整

原检测表字段可保留，但展示表建议增加：

| 类别 | 中文名称 | 置信度 | 关注等级 | x1 | y1 | x2 | y2 |
|---|---|---:|---|---:|---:|---:|---:|

导出 CSV 和 JSON 时也建议追加：

```text
中文名称
关注等级
置信度解释
```

## 4. 类别中文映射

建议统一放在模块中：

```python
CLASS_DISPLAY_NAMES = {
    "Caries": "龋齿",
    "Periapical_Lesion": "根尖周病变",
    "Periapical Lesion": "根尖周病变",
    "Impacted": "阻生牙",
}
```

注意处理下划线和空格差异。

## 5. 代码实现建议

新增文件：

```text
src/dental_detection/result_levels.py
```

建议函数：

```python
def normalize_class_name(name: str) -> str:
    ...

def get_class_display_name(name: str) -> str:
    ...

def get_confidence_level(confidence: float) -> str:
    ...

def get_confidence_description(confidence: float) -> str:
    ...

def enrich_detection_row(det: dict[str, Any]) -> dict[str, Any]:
    ...
```

## 6. UI 展示建议

1. 检测表增加关注等级。
2. 结果区增加一段置信度说明。
3. 报告中写入关注等级。
4. 批量 Top 列表使用关注等级排序和展示。
5. AI 建议中可以引用关注等级，但不能把关注等级说成诊断结果。

## 7. 边界处理

1. 置信度为空时显示未知。
2. 置信度无法转数字时显示未知。
3. 类别未知时中文名称显示原类别名。
4. 无检测框时不要生成虚假等级。
5. 不要使用“严重”“确诊”等词替代关注等级。

## 8. 验收标准

1. 检测表显示中文类别和关注等级。
2. 不同置信度等级正确。
3. 导出报告包含关注等级。
4. 批量统计能使用关注等级。
5. 无检测框时提示合理。
6. 不出现诊断性表达。

# 功能四：结果图交互增强

## 1. 功能目标

牙科病变区域通常较小，固定尺寸的结果图可能看不清。需要增强结果图查看体验，让用户能够放大查看、下载结果图、查看疑似区域局部图。

## 2. 第一阶段建议实现

### 2.1 大图查看

在检测结果区域增加：

```text
查看高清结果图
```

可以使用 Accordion 或单独 Image 组件展示更大尺寸的结果图。

### 2.2 结果图下载

增加：

```text
下载检测结果图
```

将当前检测结果图保存为 PNG，并通过 File 组件返回。

### 2.3 疑似区域局部裁剪

根据检测框 bbox 裁剪局部区域，并在界面展示。

展示标题示例：

```text
区域 1：龋齿 | 置信度 0.82 | 重点关注
```

这比只看整图更适合牙科小病灶场景。

## 3. 代码实现建议

新增文件：

```text
src/dental_detection/visualization.py
```

建议函数：

```python
def save_result_image(image: Image.Image, storage_dir: str, image_name: str) -> Path:
    ...

def crop_detection_regions(
    image: Image.Image,
    detections: list[dict[str, Any]],

    ...
```

裁剪时建议在 bbox 周围增加 15% padding，保留上下文。

## 4. UI 实现建议

在结果区增加：

1. 高清结果图 Accordion。
2. 疑似区域局部图 Gallery。
3. 下载结果图按钮。

批量检测切换图片时，这些区域应同步更新。

## 5. 边界处理

1. 无检测框时显示“暂无疑似区域局部图”。
2. bbox 坐标越界时自动裁剪到图片范围内。
3. bbox 非法时跳过并不中断页面。
4. 下载文件名使用安全中文命名。
5. 切换批量图片时清理旧下载文件输出。

## 6. 验收标准

1. 单图检测后能查看高清结果图。
2. 能下载结果图。
3. 有检测框时能看到局部裁剪图。
4. 无检测框时提示正常。
5. 批量切换时局部图同步更新。
6. 原三图展示不受影响。

# 功能五：病例记录增强

## 1. 功能目标

当前病例记录可以保存和查看，但更像简单 JSON 文件列表。需要增强为可搜索、可筛选、可删除、可导出的本地记录管理功能。

## 2. 第一阶段建议

继续使用 JSON 文件，不要急着上数据库，降低改动风险。

新增统一病例管理模块：

```text
src/dental_detection/case_store.py
```

## 3. 功能清单

### 3.1 病例搜索

搜索范围：

- 病例编号。
- 图片名称。
- 病例备注。
- 检测类别。
- 辅助建议。

1. 可以搜索病例。

# 功能六：图像质量检测增强

## 1. 功能目标

当前已经有图像尺寸、亮度、对比度、宽高比提示。建议继续增强图像质量检测，让系统更专业，也减少用户对低质量图像结果的误读。

## 2. 新增质量维度

建议新增：

1. 模糊程度。
2. 过曝比例。
3. 欠曝比例。
4. 图像过小风险。
5. 极端裁剪风险。
6. 是否建议开启 CLAHE。
7. 疑似非牙科影像提醒。

## 4. 模糊检测建议

使用 Laplacian 方差估计：

```python
blur_score = cv2.Laplacian(gray, cv2.CV_64F).var()
```

建议规则：

```text
blur_score < 50：图像可能明显模糊
50 <= blur_score < 100：图像清晰度一般
blur_score >= 100：未发现明显模糊风险
```

这些阈值只作为提示，不应写成绝对判断。

## 5. 过曝与欠曝检测

可以统计灰度图中接近黑色和接近白色的像素比例。

建议规则：

```text
灰度值 <= 10 的像素比例：欠曝比例
灰度值 >= 245 的像素比例：过曝比例
```

如果比例较高，则提示：

```text
图像存在较多过亮区域，可能影响细小病变识别。
图像存在较多过暗区域，建议确认曝光或阅片设置。
```

## 6. 综合质量等级

建议输出：

- 良好。
- 一般。
- 较差。

示例：

```text
图像质量等级：一般
提示：图像对比度偏低，建议尝试开启 CLAHE 增强后对照查看。
```

不要输出“不可诊断”这种强医疗判断，可以写“可能影响模型识别稳定性”。

## 7. UI 展示建议

当前质量提示框继续保留，但内容更结构化：

```text
图像质量提示

基础信息：
- 尺寸：xxxx x xxxx
- 平均亮度：xx.x
- 对比度估计：xx.x
- 模糊评分：xx.x

综合判断：
- 图像质量等级：一般

风险提示：
- 对比度偏低，可能影响细小病变识别。
- 建议尝试开启 CLAHE 增强后对照查看。
```

## 8. 报告联动

正式报告中写入图像质量结果。

批量总览中可以统计：

- 质量较差图片数量。
- 建议复查图像质量的图片列表。

## 9. 验收标准

1. 单图检测后显示增强后的质量提示。
2. 模糊、过曝、欠曝至少能计算并展示。
3. 质量结果写入正式报告。
4. 批量检测可统计质量较差图片。
5. 不因图像格式或灰度图导致报错。
6. 不输出诊断性结论。
