# 第二档_P1重要体验增强功能优化建议

## 第二档说明

第二档功能不是最紧急，但做完后项目会更像一个完整、易用、面向普通用户的前台识别软件。这些功能同样不涉及训练、复训练或服务器任务。

第二档包含六个功能：

1. 模型信息说明页。
2. 模型卡片式选择。
3. 检测历史记录。
4. 批量报告合并导出。
5. AI 建议结构化。
6. 检测结果图例与类别说明。

---

# 功能一：模型信息说明页

## 1. 功能目标

用户不需要了解训练过程，但需要知道当前模型能识别什么、适合什么输入、有什么局限。模型信息说明页的目的不是展示训练平台，而是让用户理解当前识别系统的能力边界。

## 2. 页面内容建议

新增“模型说明”页面或在设置中新增“模型说明”子页。

建议展示：

1. 当前模型名称。
2. 模型类型。
3. 可识别类别。
4. 输入图片要求。
5. 推荐使用场景。
6. 不适用场景。
7. 结果解释说明。
8. 安全声明。
9. 可选：模型指标摘要。

## 3. 模型说明内容示例

```text
当前模型用于牙齿病变区域辅助识别，可检测以下类别：

1. 龋齿
2. 根尖周病变
3. 阻生牙

模型输出为疑似区域检测框和置信度。置信度表示模型对检测框的把握程度，不等同于疾病严重程度，也不能替代专业牙科医生诊断。
```

## 4. 不适用场景说明

应明确提示：

```text
本系统不适用于最终诊断。
本系统不提供治疗方案。
本系统不提供药物建议。
低质量图像可能影响识别结果。
未检测到目标不代表不存在病变。
```

## 5. 代码实现建议

新增文件：

```text
src/dental_detection/model_info.py
```

建议函数：

```python
def get_model_info_cards(model_registry: dict) -> list[dict]:
    ...

def format_model_info_markdown(model_info: dict) -> str:
    ...
```

## 6. 验收标准

1. 用户可以在界面查看当前模型说明。
2. 类别中文解释清楚。
3. 模型局限性明确。
4. 不出现训练平台相关入口。
5. 安全声明完整。

# 功能二：模型卡片式选择

## 1. 功能目标

当前模型选择偏工程化，需要用户看到模型目录、模型路径、刷新、使用选中模型等。普通用户不适合频繁处理路径。建议将模型选择优化为卡片式选择，降低理解成本。

## 2. 当前问题

现有模型选择更适合开发者：

- 需要理解模型目录。
- 需要选择 .pt 文件。
- 需要知道主模型和对比模型。
- 路径展示较长。
- 普通用户可能误选错误文件。

## 3. 推荐设计

在普通模式下显示模型卡片：

```text
推荐模型
说明：综合表现较均衡，适合日常识别。

原始模型
说明：YOLOv8m 原始结构候选模型。

轻量优化模型
说明：结构更轻，推理资源消耗更低。
```

每张卡片包含：

1. 模型名称。
2. 简短说明。
3. 可识别类别。
4. 推荐标签。
5. 选择按钮。

路径配置放入“高级设置”。

## 4. UI 建议

普通用户看到：

```text
模型选择

[推荐模型]  [使用]
[原始模型]  [使用]
[轻量模型]  [使用]
```

高级用户可以展开：

```text
高级模型路径设置
```

里面保留现有模型目录扫描和路径输入。

## 5. 代码实现建议

在 `model_info.py` 中提供卡片数据：

```python
def build_model_cards(model_registry: dict, default_model_name: str) -> list[dict]:
    ...
```

app.py 中根据卡片生成 Radio 或按钮。

## 6. 边界处理

1. 模型文件不存在时卡片显示不可用。
2. 默认模型不存在时给出明确提示。
3. 高级路径设置仍可使用。
4. 不要删除现有路径配置能力。

## 7. 验收标准

1. 普通用户可以通过卡片选择模型。
2. 高级路径配置仍保留。
3. 模型文件缺失时提示明确。
4. 单图和批量检测使用当前选择模型。
5. 设置保存后重启仍生效。

# 功能三：检测历史记录

## 1. 功能目标

病例记录适合保存重要结果，但用户可能只是想找回最近检测过的图片和结果，不一定每次都手动保存病例。因此建议新增“检测历史记录”。

## 2. 历史记录与病例记录的区别

病例记录：

- 用户主动保存。
- 带病例编号和备注。
- 更正式。

检测历史：

- 系统自动保存最近检测摘要。
- 用于快速找回刚刚检测过的结果。
- 可以设置是否保存图片。
- 可以设置保存数量上限。

## 3. 历史记录字段

建议保存：

```text
检测时间
图片名称
检测类别
检测框数量
最高置信度
关注等级
模型名称
是否使用 CLAHE
报告路径
```

默认不保存原始图片，避免隐私风险。

可选保存：

- 结果图缩略图。
- 检测结果图。
- 原始图。

原图保存默认关闭。

## 4. 存储建议

新增目录：

```text
history
```

新增模块：

```text
src/dental_detection/history_store.py
```

可以先使用 JSON Lines 文件：

```text
检测历史.jsonl
```

每次检测追加一行，避免频繁读写大 JSON。

## 5. 前端建议

新增“检测历史”页或放到“病例记录”页下方。

字段表格：

| 检测时间 | 图片名称 | 检测数量 | 涉及类别 | 最高置信度 | 关注等级 | 模型 |
|---|---|---:|---|---:|---|---|

操作：

- 查看详情。
- 导出报告。
- 删除历史。
- 清空历史。
- 保存为病例。

## 6. 设置项建议

在设置中增加：

```text
自动保存检测历史
保存检测结果图
保存原始上传图
历史记录最多保留数量
```

默认：

- 自动保存检测历史：开启。
- 保存检测结果图：开启或关闭均可。
- 保存原始上传图：关闭。
- 最多保留：100 条。

## 7. 验收标准

1. 单图检测完成后生成历史记录。
2. 批量检测可以生成多条历史记录。
3. 历史记录可查看。
4. 历史记录可删除。
5. 可以从历史保存为病例。
6. 默认不保存原始图或明确提示用户。
7. 清空历史不会删除病例记录。

# 功能四：批量报告合并导出

## 1. 功能目标

当前批量导出主要是数据包形式。对于普通用户来说，批量检测后更希望获得一个合并报告，里面有总览和每张图片的检测结果。

## 2. 报告结构建议

批量报告建议包含：

1. 报告标题。
2. 生成时间。
3. 批量检测总览。
4. 类别统计。
5. 重点关注图片列表。
6. 每张图片的检测结果。
7. 失败图片列表。
8. 安全声明。

## 3. 每张图片小节

每张图片包含：

```text
图片名称：xxx.png
检测框数量：3
涉及类别：龋齿、根尖周病变
最高置信度：0.82
关注等级：重点关注
```

然后插入检测结果图和检测框表格。

## 4. 推荐实现

第一阶段实现 Word 批量报告：

```text
导出批量 Word 报告
```

后续再考虑 PDF。

## 5. 代码实现建议

复用 `reporting.py`：

```python
def export_batch_docx_report(batch_state: list[dict], batch_summary: dict, output_dir: Path) -> Path:
    ...
```

## 6. 边界处理

1. 批量结果为空时不可导出。
2. 部分失败时报告仍能导出。
3. 图片较多时控制图片尺寸，避免报告过大。
4. 报告文件名包含时间戳，避免覆盖。
5. 报告中不暴露 API Key。

## 7. 验收标准

1. 批量检测后可以导出合并 Word 报告。
2. 报告首页包含总览。
3. 每张成功图片都有结果小节。
4. 失败图片被列出。
5. 报告可以正常打开。
6. 原批量 ZIP 导出不受影响。

# 功能五：AI 建议结构化

## 1. 功能目标

当前 AI 建议可用，但如果输出是一大段自然语言，用户阅读成本较高。建议统一 AI 建议结构，让输出更稳定、更像软件功能。

## 2. 输出结构建议

AI 建议统一为：

```text
检测摘要：
...

需要关注的位置：
...

复查建议：
...

注意事项：
...

安全声明：
本结果仅供辅助参考，不能替代专业牙科医生诊断。
```

## 3. 医生版与患者版

可以在设置中增加：

```text
AI 建议风格
- 简洁版
- 医生版
- 患者版
```

### 医生版

更偏专业：

- 保留类别名。
- 保留置信度。
- 保留 bbox 或区域描述。
- 语言简洁。

### 患者版

更易懂：

- 使用中文类别。
- 少用技术术语。
- 强调需要医生复核。
- 不吓唬用户。

## 4. Prompt 修改建议

默认 Prompt 应明确要求：

1. 不分析图片本身，只基于 YOLO 检测结果。
2. 不输出诊断结论。
3. 不提供处方。
4. 不提供药物剂量。
5. 使用固定结构输出。
6. 中文输出。
7. 不超过指定字数。

## 5. AI 关闭时的内置建议

即使 AI 关闭，也应使用同样结构生成内置建议，保持界面一致。

建议把 `default_advice` 改造成结构化输出。

## 6. 验收标准

1. AI 建议按固定结构输出。
2. AI 关闭时内置建议也结构化。
3. 报告中写入结构化建议。
4. 不上传图片给 AI。
5. 不出现诊断性表述。
6. 用户可切换建议风格。

# 功能六：检测结果图例与类别说明

## 1. 功能目标

当前类别主要是英文名称，普通用户不一定理解。建议增加中文类别说明和颜色图例。

## 2. 图例内容

示例：

```text
图例：
红色：龋齿
蓝色：根尖周病变
绿色：阻生牙
```

具体颜色应与绘制检测框代码保持一致。

## 3. 类别说明

每个类别给出简短说明：

```text
龋齿：模型检测到疑似龋坏相关区域，建议结合症状和牙科检查复核。
根尖周病变：模型检测到疑似根尖周相关异常区域，建议由牙科医生结合影像复查。
阻生牙：模型检测到疑似阻生牙相关区域，建议咨询牙科医生评估。
```

## 4. 展示位置

可以放在：

1. 检测结果图下方。
2. 检测表上方。
3. 模型说明页。
4. 报告中。

## 5. 验收标准

1. 用户可以看到类别中文名。
2. 图例颜色与检测框颜色一致。
3. 报告中包含图例。
4. 检测表中显示中文类别。
5. 类别说明不构成诊断。
