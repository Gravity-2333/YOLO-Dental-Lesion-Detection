# Git 协作准则

这份文档记录当前项目希望 AI 助手遵守的 Git 使用方式，也可以复制到其他项目里作为协作约定。

## 基本原则

- 不要每次小修改都立刻 commit 或 push。
- 每次功能修改、问题修复或配置调整，都要记录到项目进度文档中，例如 `docs/项目进度/AI协作进度记录.md`。
- 平时可以根据需要 `git add` 暂存确认过的相关文件，但只有在关键节点再 commit。
- commit 信息使用中文，简洁说明本次提交的主要目的。
- push 只在关键节点执行，例如功能完成、阶段性可运行、重要修复完成、用户明确要求推送。

## 什么是关键节点

适合 commit/push 的情况：

- 新功能已经完成并通过基本验证。
- 影响运行的 bug 已修复。
- 项目结构、依赖、模型路径等基础设施发生重要调整。
- 用户明确要求提交或推送。
- 一组相关修改已经形成清晰、可描述的阶段成果。

暂时不需要 commit/push 的情况：

- 只是调文案、参数、样式的小步试探。
- 正在排查问题，还没有确定最终方案。
- 临时日志、缓存、运行输出或本地数据路径调整。
- 被 `.gitignore` 忽略的本地数据集内部修改。

## 暂存规则

- 只暂存与当前任务相关的文件。
- 不要使用 `git add -A` 盲目加入所有变更，除非确认整个工作区都属于本次任务。
- 不提交 `__pycache__`、日志、临时输出、大型本地数据集、隐私数据。
- 如果遇到用户已有的未提交改动，先判断是否相关；无关则不要改动或暂存。

## 数据集规则

- 原始医学影像和标签默认不进入普通 Git 仓库。
- 数据集目录应写入 `.gitignore`。
- 可提交数据集配置模板，但不要提交包含个人电脑绝对路径的配置。
- 需要共享数据集时，优先考虑 Git LFS、DVC、Release 附件、网盘或受控云存储，并确认隐私与授权。

## 文档记录规则

- 每次功能增加、修改、修复，都要写入进度文档。
- 记录内容包括：做了什么、为什么做、验证情况、后续注意点。
- 遇到编码问题时，先确认是显示编码问题还是文件内容损坏；Windows PowerShell 读取 UTF-8 文件时优先使用 `Get-Content -Encoding UTF8`。
